  KEY PROPERTIES
   · Backend NEVER computes a scored number and NEVER calls the LLM.
   · Backend NEVER mutates report.json in place; decisions live separately

   · Replay is ALWAYS proxied through the backend so budget is accounted
     centrally and keys/URLs stay server-side.
   · Everything is stateless except the three files in Store.

3. BACKEND REST API (browser-facing)  — base path /api/v1
======================================================================

HEALTH & RUN CONTROL
  GET  /api/v1/health
       -> {status:"ok", report_present:bool, llm:"up|down|offline",
           replay_budget:{used,total}}
  POST /api/v1/runs
       body {kit_path?, replay_url?, mode:"backbone|full"}
       -> 202 {run_id, state:"QUEUED"}       # triggers an analysis run
  GET  /api/v1/runs/{run_id}
       -> {run_id, state:"QUEUED|RUNNING|COMPLETED|FAILED",
           stage:"DETECT|DIAGNOSE|...|WRITE_REPORT", started_at, ended_at,
           report_path?, error?}

REPORT (the one contract, read-only to the browser)
  GET  /api/v1/report
       -> full loop-report.json, with decisions merged into
          prescriptions[].approval
  GET  /api/v1/report/validate
       -> {valid:bool, errors:[...]}          # schema check status
  GET  /api/v1/report/download
       -> the raw loop-report.json file (for submission)

FINDINGS
  GET  /api/v1/findings
       -> [{id, tenant, cohort, metric, severity, is_regression,
            state, has_fix, verification_verdict, decision_state}]
  GET  /api/v1/findings/{id}
       -> one finding + its linked diagnosis + prescription + verification
  GET  /api/v1/findings/{id}/evidence
       -> {evidence:[...], timeline:[config markers], cohort_samples:[...]}
  GET  /api/v1/lookalikes
       -> findings where is_regression=false (+ not_a_regression_because)

METRICS / STANDARD / GAPS / SELF-ASSESSMENT
  GET  /api/v1/metrics             -> metrics[]
  GET  /api/v1/metrics/{id}        -> one metric + full honesty block
  GET  /api/v1/standard            -> standard[]
  GET  /api/v1/gaps                -> gaps[]   (the refusals)
  GET  /api/v1/self-assessment     -> self_assessment{}

FIX VERIFICATION & DECISION (the loop closer)
  POST /api/v1/prescriptions/{id}/replay
       body {}                                # cohort/change taken from the
                                              # prescription; budget-guarded
       -> replay result (see Replay contract §6) ; also appended to
          verifications[]
  GET  /api/v1/prescriptions/{id}/verification
       -> verifications[] entry for this prescription
  POST /api/v1/findings/{id}/decision
       body {verdict:"accepted|rejected|deferred", reason, decided_by}
       -> {ok:true, approval:{...}}           # writes prescriptions[].approval
  GET  /api/v1/decisions
       -> decision history (audit trail)

4. AGENTIC LAYER API (internal)  — base path /ai
======================================================================

These are INTERNAL. They are invoked by the backend's Run Controller and
by the orchestrator's state machine — NEVER by the browser. In the
hackathon build they are in-process Python calls with exactly these
contracts; they can be lifted to HTTP if we ever split the process. Each
is tagged [DET] or [LLM]; the [DET] ones must be reproducible and are the
only ones allowed to produce a scored fact.

RUN CONTROL
  POST /ai/run                 [DET orchestration]
       body {kit_path, replay_url?, mode:"backbone|full"}
       WHAT IT DOES: runs the whole state machine end to end and writes
       loop-report.json. In "backbone" mode it skips every [LLM]/[NET]
       stage and still emits a valid, scoring report (the sealed-run
       safety net). Returns {run_id, report_path, machine_scoreable:true}.
  GET  /ai/run/{id}/status     [DET]
       WHAT IT DOES: returns current stage + per-stage timings for the
       Run Status view.

PIPELINE STAGES (called in order by the orchestrator)
  POST /ai/detect              [DET]
       IN {tenant?, window?}   OUT candidate findings
       WHAT IT DOES: stratifies cohorts (tenant x intent x agent x tool x
       week), picks baselines (peer/historical/standard), runs the three
       fault detectors (kb.gap, silent-tool-200, standard-relative) and
       the three lookalike guards. Produces findings[] with is_regression
       set. NO LLM — detection is a fact.
  POST /ai/validate-lookalikes [DET]
       WHAT IT DOES: confirms decoys (traffic_mix / load / judge_change)
       as is_regression=false with not_a_regression_because. Also applies
       denominator guards (v2_flow exclusion, customer_ref cardinality
       refusal).
  POST /ai/diagnose            [DET]
       IN finding_id           OUT diagnosis
       WHAT IT DOES: assigns cause_class (closed enum) and attributes the
       responsible config change (kind + day, within +/-2), rejecting
       nearby non-causal markers. NO LLM — cause is derived from signals,
       not guessed.
  POST /ai/mine-standard       [DET]
       WHAT IT DOES: mines "what good looks like" (top-decile per cohort),
       freezes the golden set + version. Feeds the standard-relative
       detector and the replay golden-set guard.
  POST /ai/impact              [DET]
       IN finding_id           OUT impact block
       WHAT IT DOES: computes conversations_affected, share_of_traffic,
       downstream counts, cost, days_running, and the derivation string
       (names the baseline + why). NO LLM.
  POST /ai/judge               [LLM]
       IN {ask|cohort, judge_version} OUT judged signal + calibration
       WHAT IT DOES: the ONLY place meaning is judged — satisfaction /
       quality / abandonment REASON (A09) / conversation topic. Versioned;
       returns agreement with human labels (never 1.00). Rule-1 firewall:
       it sees tool outputs, never raw rows, and never a logged fact.
  POST /ai/prescribe           [DET + LLM]
       IN diagnosis_id         OUT prescription
       WHAT IT DOES: [DET] maps cause_class -> change_type (closed enum) +
       target + predicted_delta (from the baseline). [LLM] drafts the
       human-readable decision prose (asking_approval_for, risk_if_
       diagnosis_wrong, would_not_ship_if). The scored fields are
       deterministic; only the prose is LLM.
  POST /ai/verify              [NET]
       IN prescription_id      OUT verification
       WHAT IT DOES: calls the replay endpoint ONCE for this fix (budget-
       accounted, cached by (tenant,change,cohort)), passes the golden
       set, records before/after + verdict + prediction_error. no_effect
       is a valid recorded result, never retried in a search loop.
  POST /ai/narrate             [LLM]
       IN finding_id           OUT narrative strings for the screen
       WHAT IT DOES: writes operator prose OVER already-computed evidence.
       Presentation only; changes no number. Degrades to templates if the
       LLM is offline.
  POST /ai/assess              [DET]
       WHAT IT DOES: aggregates prediction-vs-observed across verified
       fixes into self_assessment (cycles, per-change_type hit rate,
       downweighted). Reports the TRUE, small number — never inflated.

RULE-1 SUMMARY FOR THIS SURFACE
  [DET] endpoints (detect, validate, diagnose, mine-standard, impact,
        assess) produce every SCORED fact. They must never call the LLM.
  [LLM] endpoints (judge, narrate, and the prose half of prescribe) touch
        meaning/prose only. Breaking this boundary is disqualifying.

5. DETERMINISTIC TOOL INTERFACE (what the LLM may call)
======================================================================

Within an [LLM] stage, the model never sees raw corpus rows — it may only
call these tools, which return already-computed FACTS. (Full signatures
also in Approach-Tech.txt Appendix A.)

  get_metric(metric_id, tenant?, cohort?, window?)
       -> {value, numerator, denominator, fidelity, coverage, calibration?}
  get_cohort_metrics(tenant, dims[], metric, window?)   # stratified only
       -> [{cohort, value, n}]
  compare_baseline(tenant, cohort, metric, window)
       -> {observed, baseline, baseline_kind, baseline_why, delta}
  detect_change_points(series)      -> [{day, magnitude}]
  get_config_changes(tenant, day_range)  -> [{day,kind,target,from,to,note}]
  get_conversation(session_id)      -> session + steps  (read-only)
  search_conversations(filter)      -> [session_id,...]  (bounded)
  get_execution_steps(session_id)   -> [step,...]
  calculate_coverage(tenant, metric)-> {value, basis, excluded}
  calculate_calibration(metric, judge_version) -> {agreement, n, judge_version}
  check_measurability(ask_id)       -> {verdict, why, nearest_proxy?,
                                        why_the_proxy_misleads?, required_event?}
  mine_standard(tenant, cohort, metric) -> {best, median, deficit,
                                            exemplar_n, golden_set_version}
  create_fix(diagnosis_id)          -> {change_type, target, predicted_delta}
  request_replay(tenant, change, cohort, golden_set)  # budget-accounted
       -> replay response (see §6)
  get_human_labels(kind)            -> labels for calibration

6. SCHEMAS
======================================================================

Four schema families:
  A. loop-report.json   — OUTPUT contract  (FIXED by organizers)
  B. catalog.json       — INPUT contract   (FIXED by organizers)
  C. Corpus in-memory model + agentic contracts  (OURS)
  D. Backend DTOs + decisions.json + replay contract (OURS / provided)

Notation below: name:type; "?" = optional; "|" = enum; [] = array.

----------------------------------------------------------------------
6.A  loop-report.json  (OUTPUT CONTRACT — validate against draft-07)
----------------------------------------------------------------------
REQUIRED top-level: team, corpus, metrics, findings, diagnoses, gaps.

LoopReport {
  team: string
  corpus: string                 # = manifest.corpus_variant
  generated_at?: string
  system_notes?: string          # what is real / stubbed (Framing points)

  metrics: Metric[]              (required, minItems 1)
  standard?: StandardEntry[]     (optional — loop points)
  findings: Finding[]            (required)
  diagnoses: Diagnosis[]         (required)
  prescriptions?: Prescription[] (optional)
  verifications?: Verification[] (optional)
  gaps: Gap[]                    (required)
  self_assessment?: SelfAssessment
}

Metric {
  id: string                     (req)
  name?: string
  ask_id: string                 (req)  # which asks.md item this answers
  grain?: "session"|"step"|"turn"
  fidelity: "measured"|"judged"|"derived"   (req)
  coverage: {                    (req)
     value: number(0..1)         (req)
     basis: string               (req)
     excluded?: string[]         # e.g. ["agent_kind = v2_flow"]
  }
  calibration?: {                # required for judged metrics; must be <1.0
     agreement: number(0..1)     (req)
     n: integer                  (req)
     judge_version?: string
  } | null
  plan: {                        (req)
     source: string              (req)
     filter: string              (req)
     denominator: string         (req)
     breakdowns?: string[]
     alternatives_offered?: string[]
  }
}

StandardEntry {
  tenant?: string
  cohort: object                 (req)  # e.g. {"intent":"order_status"}
  metric: string                 (req)
  best: number                   (req)  # top-decile value (the standard)
  median: number                 (req)
  deficit?: number
  exemplar_n?: integer
  golden_set_version?: string
  derivation?: string
}

Finding {
  id: string                     (req)
  tenant: string                 (req)
  cohort: object                 (req)  # {"intent":...} / {"tool":...} /
                                        # {"agent_id":...}
  metric: string                 (req)
  window: { from_day:int, to_day:int }  (req)
  observed?: number
  expected?: number
  is_regression: boolean         (req)
  not_a_regression_because?: string     # REQUIRED-in-practice for decoys
  severity?: "low"|"medium"|"high"|"critical"
  evidence?: string[]

  # --- REQUIRED WHEN is_regression = true (schema if/then) ---
  impact?: {
     conversations_affected: integer    (req)
     share_of_traffic: number(0..1)     (req)  # of tenant traffic in window
     downstream?: object                # {would_have_resolved_at_baseline,
                                        #  unplanned_handoffs, abandoned,
                                        #  extra_turns, repeat_contacts}
     cost_usd?: number|null             # null is an honest answer
     days_running?: integer
     derivation: string                 (req)  # re-checkable; names baseline
  }
  audience?: ("business_owner"|"agent_builder"|"platform_owner")[]  # req if reg
  if_nothing_changes?: string           # req if regression
}

Diagnosis {
  id: string                     (req)
  finding_id: string             (req)  # MUST link to a Finding.id
  cause_class: "kb.gap"|"tool.contract_break"|"tool.outage"|
               "prompt.regression"|"model.change"|"routing.error"|
               "traffic_mix"|"load"|"judge_change"|"unknown"   (req)
  confidence?: number(0..1)
  attributed_change?: { kind:string, day:integer } | null
  evidence?: string[]
}

Prescription {
  id: string                     (req)
  diagnosis_id: string           (req)  # MUST link to a Diagnosis.id
  change_type: "kb.add"|"kb.synonym"|"prompt.edit"|"tool.validate"|
               "tool.fallback"|"routing.change"|"revert"|"no_action" (req)
  target: string                 (req)
  description?: string
  autonomy_rung?: "L0"|"L1"|"L2"|"L3"|"L4"
  predicted_delta: { metric:string, from:number, to:number }  (req)
  decision: {                    (req)
     asking_approval_for: string (req)  # in the operator's words
     risk_if_diagnosis_wrong: string    (req)
     would_not_ship_if: string          (req)
  }
  approval?: {                   # written by the human decision gate
     verdict: "accepted"|"rejected"|"deferred"
     decided_by: string
     reason: string
     at: string
  }
}

Verification {
  prescription_id: string        (req)
  replay_run_id: string          (req)  # MUST start "rp_" to be scored
  metric?: string
  before?: number
  after?: number
  golden_set_pass?: boolean|null
  verdict: "improved"|"no_effect"|"regressed"   (req)
  prediction_error?: number      # predicted delta - observed delta
}

Gap {
  ask_id: string                 (req)
  verdict: "NOT_MEASURABLE"|"REQUIRES_NEW_JUDGE"|"COVERAGE_TOO_LOW"|
           "CARDINALITY_REFUSED"                (req)
  why: string                    (req)
  nearest_proxy?: string
  why_the_proxy_misleads?: string
  required_event?: { name:string, grain:string, fields:string[], owner:string }
}

SelfAssessment {
  cycles?: integer               # >=3 earns full loop credit
  prescription_accuracy?: { <change_type>: {n:int, hit_rate:number,
                            mean_prediction_error:number} }
  downweighted?: string[]
  notes?: string
}

----------------------------------------------------------------------
6.B  catalog.json  (INPUT CONTRACT — read, never modify)
----------------------------------------------------------------------
Structure we consume (fixed by organizers):

Catalog {
  catalog_version, corpus_variant, note
  entities: { session|step|turn|config_change: {grain, table, key,
              valid_measures[], warning?} }
  joins: [{ from, to, validity:"SOUND"|"SOUND_WITH_CARE"|
            "UNSOUND_ACROSS_JUDGE_VERSIONS", cardinality?, note? }]
  fields: { "<entity.field>": { kind:"dimension"|"measure",
            closed_set?[], semantics?, nullable?, fidelity?, requires?,
            cardinality_budget? } }
  capabilities: [{ id, fidelity, grain, class:"canonical"|
            "derivable_not_declared"|"NOT_MEASURABLE"|"requires_new_judge",
            coverage?{<tenant>:number}, coverage_basis?, definition?,
            judge_versions?[], calibration_available?, calibration_basis?,
            blocker?, nearest_proxy?, required_event? }]
  cardinality_budgets: { "<field>": integer, _rule }
  milestones: { <tenant>: { <intent>: [milestone,...] } }
  tenants:   { <tenant>: { label, vertical, agents[], tools[], kb_docs,
               v2_flow_share } }
}

We treat capabilities[].class as the measurability registry that drives
the /ai gaps logic (§4). coverage[] drives the coverage denominators.

  agent_kind:"v3_agent"|"v2_flow", model, prompt_version, kb_version,
  turns:int, duration_s:int, cost_usd:float,

  milestones_reached:[str], milestones_total:int,
  quality_score:float, judge_version:"v1"|"v2", csat:float|null,
  custom_dims:{ customer_ref, segment:"mass"|"affluent"|"priority" }
}
Step {
  session_id, step_seq:int, day:int,
  step_type:"turn"|"llm_call"|"tool_call"|"kb_lookup"|"routing"|
            "guardrail"|"handoff",
  agent_id, agent_kind, intent, tool_name?, turn_index?,
  outcome:"ok"|"error"|"timeout"|"max_iterations"|"blocked",
  error_class?:str|null, status_code?:int, response_bytes?:int,
  result_field_count?:int, retry_count?:int, kb_hit?:bool,
  kb_top_score?:float, milestone?:str|null, duration_ms:int,
  cost_usd?:float, input_tokens?:int, output_tokens?:int
}
ConfigChange { day:int, date, tenant("*"=all),
  kind:"kb"|"tool"|"prompt"|"model"|"routing"|"judge",

# Agentic contracts (LLM structured outputs — MUST use report enums)
JudgeVerdict {
  target_id, judge_version, dimension:"satisfaction"|"quality"|
  "abandonment_reason"|"topic", value, rationale, evidence_refs:[str]
}                 # value space bounded per dimension; NEVER a logged fact
PrescriptionDraft {
  diagnosis_id,
  change_type: <loop-report change_type enum>,   # enum-bounded
  target,
  decision:{ asking_approval_for, risk_if_diagnosis_wrong, would_not_ship_if }
}                 # predicted_delta is filled DETERMINISTICALLY, not by LLM
NarrativeBlock {
  finding_id, what_happened, why, cost_of_inaction   # prose only
}
RunState {
  run_id, mode:"backbone"|"full",
  stage:"LOAD"|"COMPUTE"|"DETECT"|"VALIDATE"|"DIAGNOSE"|"STANDARD"|
        "PRESCRIBE"|"REPLAY"|"VERIFY"|"DECISION_PENDING"|"WRITE"|"DONE",
  llm:"up"|"down"|"offline", replay_used:int, timings:{<stage>:ms}
}

RunStatus   { run_id, state:"QUEUED"|"RUNNING"|"COMPLETED"|"FAILED",
              stage, started_at, ended_at?, report_path?, error? }

DecisionRequest { verdict:"accepted"|"rejected"|"deferred",
                  reason:string, decided_by:string }

# decisions.json  (append-only; merged into prescriptions[].approval)
DecisionRecord  { finding_id, prescription_id,
                  verdict:"accepted"|"rejected"|"deferred",
                  reason, decided_by, at:ISO8601 }

# Replay contract — mirrors kit replay/serve.py (do NOT modify serve.py)
ReplayRequest {
  team, tenant,
  change:  { type:<change_type enum>, target, description? },
  cohort:  { intent, from_day:int, to_day:int },
  golden_set: [session_id, ...]
}
ReplayResult {
  run_id: "rp_xxxxxxxx",              # MUST start "rp_" for scoring
  team, runs_used:int, run_budget:40,
  tenant, change, cohort,
  metric: "resolution_rate"|"median_turns",
  before:number, after:number, delta:number,
  verdict: "improved"|"no_effect"|"regressed",
  golden_set: { replayed:int, regressed:int, pass:bool|null },
  sessions_replayed:int, note
}
NOTES:
  · Budget is 40 calls per team TOTAL. Backend proxies & accounts centrally.
  · A fix only moves the metric if change.type addresses the real cause;
    no_effect is a valid, recorded outcome (not an error, not retried).
  · metric = median_turns for prompt faults, resolution_rate otherwise —
    predicted_delta.metric must match.
